# 영어·일본어 페르소나 가창 진단 · 2026-10-10

사용자 요청으로 무료 로컬 ACE-Step 영어·일본어 원곡을 각 30초 생성하고, 같은 언어별 분리 보컬을 Seed-VC CFG 0.9로 아라·서연에 각각 변환했다. 직접 작성한 가사이며 외부 곡·유료 API를 사용하지 않았다. 언어는 ACE-Step의 `vocal_language`에 각각 `en`, `ja`를 명시했다.

운영 API의 한국어 고정 경로와 구분하기 위해 `services/music/probe_multilingual_song.py` 진단 CLI를 추가했다. 기존 입력 길이 검증 함수에 언어를 전달할 수 있게 했으며, 기본값은 계속 `ko`다. NAS API·웹앱의 요청 규약이나 지원 표시를 바꾸지 않았다. 이 결과만으로 영어·일본어 운영 지원이 적용됐다고 주장하지 않는다.

| 언어 | 원곡 로딩 | 원곡 추론 | 아라 변환 실행 | 서연 변환 실행 |
| --- | ---: | ---: | ---: | ---: |
| 영어 | 1.454초 | 11.680초 | 14.766초 | 14.612초 |
| 일본어 | 1.512초 | 11.036초 | 15.126초 | 14.741초 |

원곡 생성 단계 CUDA 할당 최대는 영어 8091.65MiB, 일본어 8091.79MiB였다. 보컬 분리·반주 합성·인코딩·서비스 복구를 포함한 전체 진단은 149.316초였다. 두 원곡과 네 변환 WAV는 전체 PCM 디코딩·유한 값·피크·길이를 확인했고 모두 30초·48kHz·2채널이다. MP3는 생성·합성 단계의 인코더 전체 디코딩 검증과 각 변환본의 추가 전체 디코딩 검사를 통과했다. 각 언어의 아라·서연 변환 메타데이터에서 동일 입력 보컬 SHA-256 및 CFG 0.9를 확인했다.

실행 중인 Worker와 bridge가 idle인지 확인하고 잠시 정지한 뒤 GPU 잠금으로 진단을 순차 실행했다. finally에서 기존 자동 시작 경로로 복구했으며 종료코드 0, Worker acceptingJobs=true·activeJobId=null·error=null을 확인했다. 운영 기본 CFG 0.9는 유지했고 유료 호출·신규 모델 다운로드는 0이다. 한국어 입력 검증 회귀 테스트 2개 및 진단 CLI 구문 검사 통과.

로컬 출력은 `artifacts/multilingual-persona-2026-10-10/`에 보존했다. 언어별 `lyrics.txt`, `source/original.wav`·`original.mp3`, `ara/song.wav`·`song.mp3`, `eve/song.wav`·`song.mp3`, 측정 보고서가 있다. 비교 프리뷰는 동일 5~25초 구간을 원곡 20초 → 1초 쉼 → 아라 20초 → 1초 쉼 → 서연 20초 순서로 연결한 62초 음원이다. 모든 프리뷰에 같은 gain을 적용하고 시간 늘이기는 하지 않았다.

사용자는 영어·일본어 비교 음원을 듣고 “자연스럽게 들림”이라고 확인했다. 해당 진단 출력의 청취 승인으로 기록하며 모든 가사·음역·장르의 품질 보장으로 확대하지 않는다. 후속 1.36.0 작업에서 언어 선택의 NAS API·Windows Worker·Grok 웹앱 통합을 진행한다. 운영 배포·실제 API 검증은 별도 출시 기록에 남긴다.
