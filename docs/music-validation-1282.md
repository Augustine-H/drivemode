# 반복 가사 보존·개선 후보 검증 — 1.28.2 (2026-10-06)

## 제품에 반영한 수정

`recognition_text.py`의 압축률 검사는 반복 후렴과 Thai의 UTF-8 문자에도 높게 나올 수 있다. 압축률이 2.4를 넘었다는 이유만으로 구간 전체를 삭제하던 처리를 수정했다. 긴 반복 문장은 인식 원문과 구간 결과에 보존하며, 오인식 또는 정상 후렴일 수 있다는 경고를 함께 반환한다. 전체 결과가 1–3자 단위만 32회 이상 반복하고 정규화된 길이가 96자 이상인 경우에는 기존 제외 목적을 유지한다. standalone 자막 출처 제외·동일 디코더 1회 재시도·무음/저음량 사전 검사는 유지한다. 한국어·태국어·영어 후렴 보존, 일부 루프 때문에 앞의 가사가 삭제되지 않음, 전체 짧은 문자 루프 제외를 테스트했다.

이 수정은 **정보 손실 방지이며 ASR 정확도 향상 보장이 아니다**. 동일 Thai 입력에서 기존 압축 필터가 버리던 두 번째 구간을 보존하면 CER가 80.56% → 84.72%로 오히려 증가했다. 보존한 단어가 모두 맞다고 표시하지 않는다. 기존 저장 결과나 사용자 수정본은 소급 변경하지 않는다.

기본 모델, 언어 선택, 창 길이, GPU 큐, API 형식은 바꾸지 않는다. 버전은 1.28.2이며 저장 형식/백업 호환 버전은 유지한다. 아래 후보 모델·반주 분리·BPM 설정·입력 태그 변경은 기본 동작으로 적용하지 않았다.

## Thai/Vietnamese 실제 가창 비교

이전 [1.28.1 검증](music-validation-1281.md)과 같은 전체 녹음·시간 자막 정답을 사용했다. Thai 44.234초/문자 기준, Vietnamese 62.145초/단어 기준, 30초 창·3초 겹침, 동일 구간 합치기, 현재 결과 보존 검사다. 정답·곡 제목을 모델에 전달하지 않았다. 각 언어 한 사례이며 일반적 언어 성능이 아니다. 자막 정답을 독립적인 청취자가 재검수한 결과도 아니다.

| 방식 | Thai CER | Vietnamese WER |
|---|---:|---:|
| Qwen 기본 입력, 현재 보존 검사 | 84.72% | 97.26% |
| 언어 전용 Whisper small, greedy | 372.22% | 100.00% |
| 언어 전용 Whisper small, beam 5 | 418.98% | 142.47% |
| HDEMUCS 보컬 분리 → Qwen | 82.41% | 100.00% |

100%를 넘는 오류율은 삽입·반복 오류가 많다는 뜻이며 100%로 잘라 표시하지 않는다. 언어 전용 모델에서도 가창이 제대로 인식되지 않았고 보컬 분리도 일관된 개선을 보이지 않았다. 검증한 후보를 기본 모델로 교체하지 않는다. 현재 Thai/Vietnamese의 가창 받아쓰기는 실사용 정확도가 충분하지 않다.

고정 모델 및 로딩 시간:

- [Qwen/Qwen3-ASR-1.7B-hf](https://huggingface.co/Qwen/Qwen3-ASR-1.7B-hf): `bcd2b5b7f32b480ab5790554cfa8347f246a14f3`, BF16/SDPA/greedy, 이 비교 로딩 43.460초. 이전 3.907초와 환경·캐시 상태가 달라 단순 속도 우열로 해석하지 않는다.
- [biodatlab/whisper-th-small-combined](https://huggingface.co/biodatlab/whisper-th-small-combined): `956bcd8fbcb69c053b3116e2f21c636db5510a79`, FP32/SDPA, 로딩 6.541초, 추론 greedy 20.385초/beam5 19.728초.
- [vinai/PhoWhisper-small](https://huggingface.co/vinai/PhoWhisper-small): `a86b604c346caf7148c37512eafe783a16420adb`, FP32/SDPA, 로딩 11.968초, 추론 greedy 0.932초/beam5 19.559초. 짧은 실행은 정상 받아쓰기 성공을 뜻하지 않는다.

다운로드는 고정 revision과 파일 크기·LFS SHA-256을 확인했다. 추론은 local-only, `trust_remote_code` 없음. PhoWhisper의 공식 저장소는 safetensors가 없어 PyTorch 파일을 `weights_only=True`로 로딩했다. 사용자 음원·가사·토큰을 외부로 전송하지 않았다.

보컬 분리는 캐시된 `torchaudio.pipelines.HDEMUCS_HIGH_MUSDB_PLUS`, SHA-256 `a004b2790d73ffeaa535db458a1a79b539dfdbafbccc31f275d07e632ebd7816`, 8초 창/1초 겹침이다. 30초 부분만 선택하지 않고 같은 16kHz 전체 입력을 44.1kHz stereo로 변환해 분리하고 다시 16kHz mono로 변환했다. 별도 gain 보정·정답 기반 구간 선택은 없다. 원본에 없는 고주파 정보를 복원한다고 주장하지 않는다. 분리/ASR 시간은 Thai 23.169/5.878초, Vietnamese 1.273/0.647초였다.

## 보컬 생성의 반복 절 누락 후보

같은 자체 작성 가사·음악 설명·시드·길이를 고정해 6곡을 새로 생성했다. ACE-Step turbo, 고정 revision `200ba991ae448051e14b0183157e35c2d27c9fb0`, BF16/CPU offload, 8 steps/guidance 1/shift 3. 입력 가사는 생성에만 전달하며, 출력 음원의 Qwen 받아쓰기에는 힌트로 넣지 않았다.

| 길이·시드 | 기존 CER | 절/후렴 번호만 추가 | BPM metadata 90 명시 |
|---|---:|---:|---:|
| 60초·1042 | 54.23% | 45.77% | 51.41% |
| 60초·2026 | 50.70% | 34.51% | 49.30% |
| 120초·1042 | 6.67% | 미검증 | 19.49% |
| 120초·2026 | 11.79% | 미검증 | 22.56% |

번호 후보는 `[Verse]`/`[Chorus]`를 입력 순서대로 `[Verse 1]`/`[Verse 2]`, `[Chorus 1]`/`[Chorus 2]`로 표시하며 **가사 단어는 그대로 유지**했다. 60초 두 사례의 ASR 일치 지표가 개선되었으나 누락이 여전히 많고 다른 길이의 개선은 확인하지 않았다. 사용자가 가사 구조를 명시할 때 참고할 수 있는 입력 방식이며 입력을 자동으로 다시 쓰지는 않는다. [ACE-Step 공식 가이드](https://ace-step.github.io/ACE-Step-1.5/en/ace_step_musicians_guide)의 절/후렴 구조 표기와도 부합한다.

BPM 후보는 설명의 기존 90 BPM을 유지하며 파이프라인 `bpm=90` metadata만 명시했다. 120초에서는 악화되어 기본값으로 적용하지 않았다. CER는 ASR 오류도 포함하므로 실제 발음·자연스러움의 청취 평가가 아니다.

6곡의 generation + WAV 저장 + ASR PCM 준비 시간은 7.967–14.189초, 모델 최대 할당 VRAM 8948.12 MiB, 프로세스 RAM 최대 샘플링 12552.82 MiB. 모델 로딩 시간은 별도이며 ACE는 1.608초였다. 48kHz WAV의 실제 길이·유한 표본을 검사했다. 이번 후보는 네이티브 WAV 생성 비교이며 MP3/API 전체 시간 검증으로 바꾸어 표시하지 않는다. MP3 생성 경로는 이전 검증과 같고 수정하지 않았다.

## 검증 및 제한

- 네이티브 생성 6건, ASR 14건(생성곡 6 + 원본 Qwen 2 + 언어별 Whisper 4 + 보컬 분리 Qwen 2)을 완료했다. 벤치마크는 Worker 유휴·큐 비어 있음 확인, 해당 Worker 프로세스만 정지, 공통 GPU 잠금, finally 복구 순서로 실행했고 두 실행 모두 복구 종료 코드 0이었다.
- 실제 Worker API에서 Thai 전체 녹음과 일본어 사용자 녹음을 연속 처리했다. Thai의 두 구간 모두 원문이 남고 보존 경고가 반환됨을 확인했으며 CER 84.72%/API 22.556초였다. 일본어 CER 4.81%/API 16.395초로 이전 결과와 같았다. 두 작업 모두 입력 base64·임시 요청 제거를 확인했다. 마지막 Worker는 `acceptingJobs=true`, 활성 작업 없음이며 NAS 브리지는 `IDLE/workerReady=true/lastError=null`이었다. 앱→NAS 전체 왕복을 새로 검증한 것으로 확대 해석하지 않는다.
- 서비스 테스트 66개, TypeScript 검사, 프로덕션 빌드가 통과했다. 첫 테스트 호출은 `PYTHONPATH`가 없어 `nas_bridge` import 한 건이 실패했고, 실제 서비스 경로를 설정해 전체 66개를 다시 통과했다. 제품 오류로 숨기거나 미통과를 성공으로 처리하지 않는다.
- 개발·빌드 화면에서 1.28.2와 기존 대화·가사·사용자 수정본이 표시되며 콘솔 error가 없음을 확인했다. 실제 폭은 개발 558px/빌드 337px, 문서 가로 넘침 없음. 레이아웃은 변경하지 않았으며 1280px 검증으로 주장하지 않는다.
- 로컬 상세 기록: `.music-runtime/lyrics-improvement-1282/report.json`, `separation/report.json`, `worker-api.json`. 공개 저장소에는 음원·전체 정답·인증정보·모델 파일을 올리지 않는다.

가창 특화 모델의 추가 비교, 번호 가사 입력의 다른 길이/곡 검증, 독립적인 청취 평가가 남았다. 이번 패치를 Thai/Vietnamese 오인식 해결 완료나 가사 일치 보장으로 발표하지 않는다.
