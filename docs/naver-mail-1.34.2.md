# 네이버 메일 후속 기능 · 1.34.2

발송 미리보기와 첨부 합계 제한에서 Base64 패딩을 제외해 실제 파일 크기를 계산한다. 154 bytes 테스트 파일은 이제 154 bytes로 표시한다.

받은 메일의 첨부파일을 앱에서 직접 다운로드할 수 있다. 인증된 HTTPS API가 계정 generation·메일함·UIDVALIDITY·UID 및 첨부 인덱스를 검증하고 읽기 전용으로 원문을 조회한다. 원문은 5MB 이하, 다운로드 파일은 3MB 이하로 제한한다. 파일명 경로/제어 문자를 정리하고 브라우저에서 application/octet-stream 다운로드로 저장하며 첨부를 실행하거나 낭독하지 않는다. 기존 계정 연결과 Google 연동을 유지한다.

답장 메시지 조회에 In-Reply-To 값을 포함해 원본 Message-ID 및 References와의 연결을 검증할 수 있다. 실제 답장 전송은 기존 SMTP 경로를 유지한다.

회귀 테스트 40개, 타입 검사, Vercel/NAS 빌드 통과. 개발 및 NAS 빌드 데스크톱/모바일 화면 검사 통과. 운영 배포 및 앱 다운로드 실계정 검증도 완료했다. 테스트 변경은 기존 본인 확인용 메일에만 적용하고 메일함과 읽음 상태를 복원한다.

실계정 검증: 기존 테스트 답장을 읽음으로 바꾸고 안읽음으로 복원했다. 받은메일함 → 내게쓴메일함 → 받은메일함 이동과 기존 테스트 전달 메일의 휴지통 이동 → 받은메일함 복원도 확인했다. 총 6회 변경, 새 발송 0회이며 최종 답장·원본은 안읽음, 전달은 기존 읽음 상태를 유지한다. 답장의 References는 원본 Message-ID와 일치한다. 업데이트 작업은 DSM 재인증 후 저장 및 수동 실행했다. 작업은 2026-10-09 15:20:00~15:20:31 KST 정상 (0)으로 완료됐다.

## 운영 다운로드·답장 연결 검증 완료

공개 앱 1.34.2 및 NAS 작업 정상 완료를 확인했다. 받은 테스트 전달 메일을 안읽음으로 잠시 변경하고 앱의 첨부 다운로드 버튼으로 파일을 받았다. 다운로드 파일은 154 bytes이며 원본과 모든 바이트 및 SHA-256 `23649a91cf8a19ae24bb22451636c6409d5deebcf905f4049f25b8fd92b5ad61`가 일치했다. 다운로드 후에도 안읽음이 유지되는 것을 UI 및 별도 읽기 전용 API 조회로 확인한 뒤 기존 읽음 상태로 복원했다. 이 검증을 포함해 변경은 8회이며 영구 삭제·새 발송은 없다.

1.34.2 메시지 조회에서 기존 답장의 In-Reply-To 및 References 모두 원본 Message-ID와 일치했다. 증빙은 `artifacts/naver-reply-header-check-1342.json`이다. 인증 없는 공개 첨부 API 요청은 401로 차단됐다. 운영 HTTPS 데스크톱·모바일 화면 검사에서 보이는 본문, 가로 넘침 없음, 콘솔/페이지 오류 없음을 확인했다. 다운로드 버튼도 좁은 실제 앱 화면에서 줄바꿈되어 표시됨을 직접 확인했다.

파일 보관본은 `artifacts/naver-app-attachment-received-20261009.txt`, 전체 검증 기록은 `artifacts/naver-mail-1.34.2-verification.json`, 화면 증빙은 `screenshots/naver-app-attachment-download.png`이다. 메일 원문 5MB 이하·다운로드 첨부 3MB 이하 제한과 앱 초안 1시간 메모리 보관 및 원본 첨부 자동 전달 미지원 범위는 유지한다.

실제 발송 미리보기에서도 동일 파일이 154 bytes로 표시됨을 확인했다. 미리보기는 취소하고 확인용 초안을 빈 초안으로 정리했으며 발송하지 않았다. 증빙은 screenshots/naver-1342-preview-bytes.png다.
