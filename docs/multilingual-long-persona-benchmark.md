# 영어·일본어 장시간 페르소나 가창 · 2026-10-10

사용자는 1.36.0 운영 영어 아라·일본어 서연 30초 원곡/변환 비교본을 듣고 “특별한 문제 없이 자연스러움”으로 확인했다. 이 두 출력의 청취 승인으로 기록한다. 이후 요청에 따라 영어·일본어 × 아라·서연 × 60·120초 총 8곡을 NAS 운영 큐로 무료 로컬 생성했다.

ACE-Step 원곡 → Demucs 분리 → Seed-VC CFG 0.9 → 반주 합성 → WAV·MP3 → NAS 보관 경로다. 60초 네 곡을 완료한 뒤 120초 네 곡을 실행했다. 가사·분위기·시드는 같은 언어·길이의 아라·서연 사이에 고정했고 변환 전 원곡 SHA-256 일치를 확인했다. 120초에는 직접 작성한 두 절과 후렴을 반복해 충분한 가창 입력을 제공했다. 요청 가사가 전부 정확히 불렸다고 판정하지는 않는다.

Worker totalSeconds를 생성+변환 시간으로 기록했다. NAS 접수→보관은 기본적으로 클라이언트 제출부터 완료 확인까지로 5초 상태 확인 간격이 포함되며 큐·업로드·네트워크 영향을 받는다. 중단 후 이어 확인한 일본어 아라 120초는 NAS의 persisted createdAt→updatedAt 시간이다. CUDA 할당 최대는 원곡 생성 단계 측정 범위다. RAM은 프로세스 working set 표본 최대이며 모든 단계의 정확한 절대 최대를 뜻하지 않는다. GPU 장치 메모리 표본은 다른 앱도 포함하므로 모델 전용 사용량으로 해석하지 않는다.

영어 서연 120초 완료 직후 일본어 아라 120초의 첫 접수에 HTTP 503이 반환되어 벤치마크가 중단됐다. 원 응답 본문은 저장하지 못했으며 상태 코드만 확인했다. 후속 확인에서 NAS workerState=READY·세 언어 지원이 정상으로 돌아왔고 동일 requestId 요청은 202로 접수됐다. 준비 상태 전환에 따른 거절로 추정하지만 최초 본문이 없어 오류 코드를 단정하지 않는다. 벤치마크는 기존 완료 결과를 재사용하고 이미 접수된 일본어 작업을 조회해 이어 확인했다. 남은 신규 접수 전에는 준비 상태를 확인했다. 모델·가사·시드·길이·CFG 변경이나 다른 엔진으로의 우회는 없다.

## 파일·동작 검증

- 8개 작업 모두 COMPLETED. 요청·모델의 singingLanguage와 페르소나 voiceId, CFG 0.9를 확인했다.
- NAS에서 WAV·MP3 16개를 다시 받아 크기·SHA-256·전체 디코딩·유한 PCM·피크·길이를 검증했다. 모두 요청 길이 60초 또는 120초·48kHz·2채널이다.
- 같은 언어·길이의 아라·서연 원곡 해시가 네 쌍 모두 일치했다. 같은 원곡의 음색 비교다.
- 종료 시 인증 Worker health acceptingJobs=true·activeJobId=null·error=null. 신규 유료 API 호출·새 모델 다운로드·학습은 0이다.
- 이번 장시간 테스트는 NAS 운영 API로 제출했다. 1.36.0 출시에서 수행한 30초 웹 생성·저장·재생 검증을 이번 8곡에서 반복했다고 주장하지 않는다.

## 청취 자료와 품질 판정

로컬 artifacts/multilingual-long-2026-10-10/에 요청 가사, NAS 결과, 원곡 WAV, 변환 WAV·MP3, 실측과 무결성 보고서를 보존했다. listening/에는 언어·길이별 후반부 비교 MP3가 있다. 60초 곡은 35~55초, 120초 곡은 95~115초를 각각 원곡 20초 → 1초 쉼 → 아라 20초 → 1초 쉼 → 서연 20초 순서로 연결했다. 동일 gain을 적용하고 시간 늘이기·발음 보정은 하지 않았다. 전체 길이 음원도 별도로 제공한다.

후반부 분리 보컬의 RMS는 참고 지표이며 들리는 가사나 발음 정확도의 증거가 아니다. 발음·긴 음·가사 누락·음색 유지에 대한 장시간 청취 평가는 아직 필요하다. 새 모델이나 강한 보정을 임의 적용하지 않았고, 문제 구간이 확인되면 해당 원곡과 변환본을 비교해 원곡 생성 문제와 변환 문제를 구분한다. 30초 청취 승인을 60·120초 품질 승인으로 확대하지 않는다.
