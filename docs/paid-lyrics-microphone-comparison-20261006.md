# Samson Go Mic 실제 노래 유료 API 비교

2026-10-06. 사용자가 휴대폰에서 재생한 한로로의 ‘사랑하게 될거야’를 Samson Go Mic로 30초 녹음했다. 같은 WAV 입력으로 Qwen 제품 Worker와 xAI·OpenAI·ElevenLabs를 비교했고, 실제 유료 요청 3회가 모두 HTTP 200으로 완료됐다. ElevenLabs는 Qwen보다 문자 오류가 1개 적었지만 큰 개선은 아니다. 기본 Qwen과 제품 버전 1.28.2를 유지하며 자동 유료 호출은 추가하지 않았다.

## 녹음과 사전 정답 확정

브라우저 장치 목록에서 `마이크(Samson Go Mic) (17a0:0305)`를 확인하고 명시적으로 선택했다. 실제 getUserMedia 트랙의 장치 표시도 같았다. 브라우저의 에코 제거·잡음 억제·자동 이득을 비활성화한 기존 제품 녹음 경로를 사용했고 30초 자동 종료를 확인했다. 녹음을 디지털 루프백이나 평가 음원 파일로 대체하지 않았다.

브라우저 Blob의 기본 다운로드가 두 번 타임아웃돼 동일 출처의 임시 로컬 내보내기 화면으로 원본을 이 PC에 보관했다. 내보내기 수신기는 127.0.0.1에만 바인딩하고 출처·Host·임의 경로·크기·WebM 헤더를 확인했으며, 보관 뒤 종료했다. 이 단계에서는 모델 추론이나 외부 API 전송을 하지 않았다. 전체 녹음 파일은 Git에 포함하지 않았다.

원본을 메타데이터 없는 16 kHz mono PCM16 WAV로 변환했다. 동일 변환 파일을 네 경로 모두에 전달했으며 해시를 검증했다.

| 입력 측정 | 결과 |
|---|---:|
| 길이 | 30.000초 |
| 평균 RMS | -29.67 dBFS |
| PCM 샘플 절대값 최대 | -9.79 dBFS |
| 절대값 ≥ 0.999인 샘플 비율 | 0% |

브라우저 화면의 최대 입력 -22 dBFS는 짧은 창의 RMS 최대이며 WAV의 단일 샘플 최대와 구분한다. 클리핑이 없다는 사실만으로 방 잡음·반주·잔향 영향을 배제하지 않는다.

사용자가 녹음 전에 가사 후보를 제공했고, 녹음 뒤 **첫 구절과 끝의 잘린 단어까지 추론 전에 확정**했다. 마지막 불완전 단어를 임의로 완성하지 않고 정답에 보존했다. 정답은 68자·22단어다. 전체 가사·모델 원문은 로컬 보관만 하며 문서에는 집계만 기록한다. 정답·채점 정책·평가 코드의 SHA-256을 첫 추론 전에 고정했고 이후 변경하지 않았다. 사용자 확인 정답이며 별도의 원어민 독립 청취 검수는 하지 않았다.

## 정확도와 처리 시간

오류율은 낮을수록 좋다. 기존 제품 평가 함수의 NFKC/casefold 및 문자 범주 L/N/M 기준으로 전체 출력의 편집 거리를 계산했다. 잘린 끝부분을 모델이 다르게 보완한 출력도 예외 없이 포함한다. 특정 모델에 맞춘 동등성 치환·가사 교정은 하지 않았다.

| 경로 | 주 CER · 68자 | 보조 WER · 22단어 | 요청→응답 시간 |
|---|---:|---:|---:|
| 현재 Qwen 제품 Worker | 16.18% · 오류 11개 | 68.18% · 오류 15개 | 17.348초 |
| xAI grok-voice-transcribe-2.0 | 20.59% · 오류 14개 | 54.55% · 오류 12개 | 1.462초 |
| OpenAI gpt-transcribe | 19.12% · 오류 13개 | 40.91% · 오류 9개 | 2.148초 |
| ElevenLabs Scribe v2 | 14.71% · 오류 10개 | 31.82% · 오류 7개 | 2.553초 |

ElevenLabs의 주 CER은 Qwen보다 **1개 오류, 1.47%p** 낮다. 단어 오류율은 띄어쓰기와 어절 분리 방식의 영향을 크게 받는다. Qwen의 WER이 높다는 사실을 같은 비율의 청취 오류로 해석하지 않으며 주 CER과 함께 읽는다. 이번 Qwen 결과에는 일반 정확도 안내만 있었고 구간 경계 병합 불확실 경고는 없었다. 앞선 분할 가창 자료에서 관측한 병합 문제를 이번 녹음의 원인으로 단정하지 않는다.

시간은 각 경로 1회의 종단 측정이며 원격 API는 네트워크와 공급자 처리를 포함한다. Qwen 모델 처리 시간은 13.847초였다. 로컬 메모리·CUDA 표본은 집계 JSON에 기록했고 공급자 RAM/VRAM은 관측하지 않았다.

## 실제 호출과 비용

한국어만 명시하고 중립 파일명 `sample-ko.wav`를 사용했다. 가사·곡명·가수·교정 프롬프트는 모델 요청에 넣지 않았다. 요청 형식은 앞선 [실제 유료 API 비교](./paid-lyrics-comparison-20261006.md)와 같으며 공급자 대체·자동 재시도·Mock 응답은 없다. 요청 원장으로 공급자/입력 중복 실행을 방지하고 최대 3회·추정 $0.10 제한을 적용했다.

사용자가 요청한 실제 마이크 비교를 위해 이번 WAV를 세 공급자에게 실제 전송했다. 키는 기존 사용자별 Windows DPAPI 저장소에서 읽고 화면·소스·Git에 넣지 않았다. 공급자당 30초에 표시 단가 xAI $0.10/시간, OpenAI $0.27/시간, ElevenLabs $0.22/시간을 적용한 추가 기본 추정 합계는 **$0.004917**이다. 실제 계정 청구·최소 과금·세금·계약 요금은 미확인이다.

## 판단

실제 마이크에서도 ElevenLabs의 작은 개선 신호를 확인했지만, 이번에는 Qwen보다 문자 오류 1개 적었을 뿐이다. 앞선 사용자 녹음은 Qwen·ElevenLabs 동률이고, 공개 무반주 한국어 자료에서는 ElevenLabs 개선 폭이 더 컸다. 가수·곡·녹음 조건에 따라 차이가 있어 전체 한국어 노래의 일반 우위를 확정하지 않는다. 한국어 유료 수동 선택 후보로 ElevenLabs를 남기고 기본 Qwen을 유지한다.

이번 측정은 한 곡·한 구간·한 번이다. Qwen 제품 전처리/분할 경로와 공급자의 전체 입력 경로를 비교했으며 모델 가중치만 통제한 시험은 아니다. 영어·일본어의 새 실제 마이크 비교는 아직 실행하지 않았다. 그 검증과 추가 독립 한국어 구간에서 효과가 유지될 때 공급자 선택·외부 음원 전송 안내·비용 제한을 제품에 연결한다. 이번 작업은 측정 문서 갱신이며 제품 소스·NAS 배포·버전 변경은 없다.
