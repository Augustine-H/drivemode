# 네이버 메일 직접 연동 · 1.34.0

네이버 IMAP·SMTP 연동을 구현했다. 기존 Google Workspace OAuth·메일 처리와 별도로 동작하며, 설정의 **네이버 메일**에서 연결한다.

- IMAP 메일함 목록, 검색, 안읽은 메일 필터, 최근 20통 조회와 본문 열기.
- 기존 대화/TTS 흐름에서 메일 요약·원문 낭독, 번호·제목 선택 후 후속 요청.
- 앱 초안 작성·수정, 답장·본문 전달, 최대 5개/합계 3MB 첨부파일 발송.
- 읽음/안읽음 변경, 메일함 이동과 휴지통 이동. 모두 변경 확인을 거치며 영구 삭제는 제공하지 않는다.
- 받는 사람·제목·본문·첨부파일을 표시하는 일회성 발송 확인. 초안 변경·계정 변경·확인 만료 후에는 이전 확인을 사용할 수 없다.
- 계정 앱 비밀번호 AES-GCM 암호화, 기존 NAS 인증/HTTPS 경계 적용, 암호화 복구 백업에 네이버 키와 암호문 포함.

초안은 네이버 서버의 임시보관함이 아닌 앱 서버 메모리에 보관한다. 기기/세션별로 한 시간 동안 유지되며, 서버 재시작·연결 해제 때 사라진다. 설정에서 편집한 초안은 저장한 후 화면을 닫아야 한다. 전달 초안에 원본 첨부파일은 자동 복사하지 않는다. 받은 원문이나 상대방에게 이미 전달된 메일은 수정하지 않는다.

개발/검증 완료:

- 타입 검사, 기본 Vercel 빌드, NAS standalone 빌드 통과.
- 네이버 및 기존 Google/NAS 경로 32개 회귀 테스트 통과.
- 개발·Vercel·NAS 빌드의 데스크톱/모바일 실제 화면 확인. 가로 넘침·콘솔 오류·페이지 오류 없음, 개발/빌드 결과 일치.
- 별도 모의 계정 화면에서 메일 조회 → 답장 초안 → 수정 → 발송 확인 취소(발송 0회) → 다시 수정 → 확인 후 모의 발송(1회) 확인. 실메일 발송 0회.
- 빌드된 NAS API에서 테스트용 NAS 인증 헤더로 상태 조회 200 및 `connected:false` 확인. 실제 네이버 계정이나 자격증명을 사용하지 않았다.
- 테스트 전용 라우트를 제거하고 최종 빌드에 모의 화면이 포함되지 않음을 확인했다.

운영 NAS 배포와 실제 네이버 계정 읽기/발송 검증은 아직 하지 않았다. 적용 패키지는 `artifacts/voice-grok-web-1.34.0-naver.zip`, 상세 검증 기록은 `artifacts/naver-mail-verification.json`에 있다. 패키지는 기존 private 설정과 Google 토큰을 포함하지 않는다. 운영 적용 시 기존 Google 데이터 볼륨과 private 설정을 유지한다. 연결은 HTTPS 앱의 네이버 메일 양식에서 앱 비밀번호를 직접 입력해야 하며, 채팅으로 비밀번호를 전달하지 않는다.

자세한 운영/인증/복구 규칙: [NAVER-MAIL.md](../services/web/nas/NAVER-MAIL.md).

## 운영 적용 준비 · 2026-10-09

사용자의 후속 진행 요청으로 기존 DSM 로그인 세션에서 1.34.0 ZIP을 `docker/voice-grok-web`에 업로드했다. File Station 업로드 대기열은 100% 완료를 표시했다. 기존 비활성 일회성 업데이트 작업을 `VoiceGrok Naver Mail Update 20261009`로 편집하여 ZIP SHA-256 검증, 독립 이미지 빌드, 기존 app/compose/start 보관, 웹 컨테이너만 교체, 상태 점검 및 실패 시 이전 이미지/파일 복원을 준비했다. 기존 private 파일, Google 데이터 볼륨, 프록시, TTS·음악 서비스는 변경 대상이 아니다. 복원 보관 경로는 `naver-backup-20261009-1340`이며 작업 실행 때 생성된다.

DSM이 root 작업 저장 전에 관리자 패스워드 재인증을 요구하여 현재 저장이 보류되어 있다. 아직 업데이트 작업을 실행하지 않았고 운영 앱은 1.33.2를 표시한다. 재인증은 사용자가 DSM 입력란에서 직접 수행해야 하며 채팅으로 비밀번호를 받지 않는다. 그 뒤 일회성 작업을 실행하고 1.34.0 표시, 기존 Google 읽기, 네이버 연결 화면과 API를 검증한다. 실제 네이버 계정 연결과 실메일 발송은 여전히 미검증이다.

## 운영 적용 완료 · 2026-10-09

사용자가 DSM 재인증을 완료한 뒤 기존 비활성 일회성 작업을 수동 실행했다. DSM 실행 결과는 14:16:13~14:17:16 KST, 정상 (0)이다. 위의 재인증 대기와 미배포 기록은 적용 전 상태이며 현재 운영 NAS는 **1.34.0**을 표시한다. 기존 등록 세션과 대화가 유지됐고, Google 연결 상태 및 일정·Drive·Gmail 읽기 API가 모두 성공했다. 네이버 연결 화면은 정상적으로 상태를 조회해 연결 대기를 표시하며 입력 양식을 제공한다. 공개 주소의 비인증 네이버 상태 조회는 401로 거부되고 TLS 검증 결과는 0이다.

운영 Tailscale HTTPS 주소의 데스크톱·모바일 smoke 검사는 모두 200, 가로 넘침 없음, 콘솔/페이지 오류 없음으로 통과했고 두 화면을 직접 확인했다. 공개 HTTPS 주소에서 네이버 설정의 PC·모바일 양식도 확인했으며 기존 대화·설정 확인 과정의 브라우저 오류 로그는 비어 있었다. 검증 자료는 `screenshots/naver-operational*.png/.json`, `screenshots/naver-live-settings*.png`, `artifacts/naver-live-network-public.json`, `artifacts/naver-live-unauth.json`이다.

배포 직후에는 실제 네이버 계정이 연결되지 않아 실메일 조회·발송이 미검증이었다. 이후 2026-10-09 사용자가 HTTPS 설정의 네이버 메일 양식에서 주소와 애플리케이션 비밀번호를 직접 입력하고 **연결 확인 후 저장**을 실행했으며, 실제 네이버 메일 읽기 테스트 완료를 보고했다. 계정 연결과 실메일 읽기는 **사용자 확인 완료**로 기록한다. 에이전트가 계정 비밀번호나 메일 본문을 열람하지 않았으며, 실메일 발송·답장·전달 및 메일함 변경은 아직 검증하지 않았다.

## 실메일 초안·발송 검증 · 2026-10-09

사용자가 본인 주소로 테스트 발송을 진행하도록 요청했다. 연결된 본인 주소를 수신자로 지정해 초안을 저장하고, 제목과 본문을 수정·재저장한 뒤 최종 미리보기를 확인해 발송을 **한 번만** 실행했다. 제목은 `[보이스 그록 테스트] 네이버 메일 초안 수정 및 발송`이며 기능 확인용 문구만 포함하고 첨부파일은 없다. SMTP 접수 성공 후 INBOX의 14:27:26 KST 메일을 열어 수정된 제목과 본문이 정확히 도착한 것을 확인했다. 본문을 읽은 후 재조회에서도 안읽음 상태가 유지됐다. 발송 후 초안 입력란이 비워지는 것도 확인했다. 연결 비밀번호는 열람하지 않았으며 답장·전달·첨부 발송·메일함 변경은 미검증이다.

별도 점검에서 **한글 검색 결과 누락**을 발견했다. 도착한 테스트 메일이 INBOX 최근 목록에는 존재하지만 전체 제목 및 짧은 `보이스` 검색 모두 결과에 나타나지 않았다. 검색 누락은 미해결 보완 항목이며 발송·수신 성공과 구분한다. 수신 본문 증빙은 `screenshots/naver-test-mail-received.png`이다.
