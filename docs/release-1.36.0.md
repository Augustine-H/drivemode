# 보이스 그록 1.36.0 · 보컬 언어 선택

보컬 생성 메뉴에서 한국어·영어·일본어를 선택한다. 기본값은 한국어·무료 로컬이다. 선택값은 작업 저장·복원, NAS 큐와 Windows Worker를 거쳐 ACE-Step의 vocal_language로 전달된다. 완성 음악 카드에 언어를 표시하며 예전 작업은 한국어로 복원한다.

ElevenLabs를 선택하면 가창 언어를 기존 스타일 지시와 함께 전달한다. 기존 비용 동의를 유지하고 언어 변경 시 동의를 초기화한다. 이번 검증에서는 신규 유료 호출을 하지 않는다. 페르소나 변환 CFG 0.9는 유지한다.

언어 기능을 보고하지 않는 구형 NAS·Worker에서는 영어·일본어 선택을 차단한다. NAS도 준비 상태가 확인되지 않은 외국어 요청은 SINGING_LANGUAGE_NOT_READY로 거절한다. 한국어 작업의 기존 규약은 호환된다.

## 검증 상태

- Python 124개, JavaScript 497개 테스트와 타입 검사 통과.
- Vercel·NAS 프로덕션 빌드 통과. 개발 및 NAS 빌드 출력의 PC·모바일 화면을 시각 확인했고 콘솔 오류·가로 넘침이 없었다. 개발 기준과 빌드 출력의 본문이 일치했다.
- 이전 무료 영어·일본어 원곡·아라·서연 진단 출력은 사용자 청취에서 “자연스럽게 들림” 평가를 받았다. 신규 운영 생성의 품질 승인으로 대체하지 않는다.
- NAS API·Worker 갱신과 NAS·Grok 웹앱 1.36.0 게시 완료. 신규 운영 큐의 두 언어 생성·파일 검증 통과.

## 배포 준비

NAS 아카이브와 이전 서비스·설정을 보존하는 복구 스크립트를 업로드했다. 사용자 DSM 재인증 후 기존 비활성 수동 작업으로 실행했고 2026-10-10 18:32:00–18:33:34 KST 정상 종료(0)를 확인했다. 새 API를 확인한 뒤 idle Worker·bridge를 기존 자동 시작 경로로 갱신했다. NAS health에 workerState=READY, singingLanguages=[ko,en,ja], singingVoices=[ara,eve]를 확인했다. 설정·비밀정보·음원 볼륨과 기존 접근 범위는 유지했다.

- 웹 아카이브 SHA-256: `2385738333afdf34c68ba48e2f755b0ec3f4e0adc2be11082b80b3c60323772a`
- API 아카이브 SHA-256: `038fd653b5b86d7ae2ec80b211c755d4ff37edbc2b8f8f6eba9c2c89f4711299`

Grok 기존 앱도 기능 커밋 `7291344d99b557fdcdb07a613ec7a6c28dafda10`을 적용해 같은 drivemode.grok.me 주소로 재게시했다. 빌더는 타입 검사·498개 테스트·빌드·개발/운영 PC·모바일 검증 통과를 보고했다. 소유자 전용 ‘나만’ 접근을 유지했고 실제 게시 화면에서 1.36.0과 세 언어 선택 가능 상태를 확인했다. 빌더 테스트 수는 로컬 497개와 환경상 다르다.

## 실제 운영 웹 생성

Grok 웹앱에서 영어·아라, NAS 웹앱에서 일본어·서연을 각각 무료 로컬·30초·페르소나 변환으로 제출했다. 진단 CLI 대신 실제 새 언어 선택 UI → NAS 큐 → Windows Worker → ACE-Step → Seed-VC → NAS 보관 경로다. 요청 singingLanguage와 결과 모델 singingLanguage가 각각 en·ja로 일치했고 변환 CFG 0.9를 확인했다.

| 언어·목소리 | 원곡 추론 | 생성+변환 | CUDA 할당 최대 | RAM 표본 최대 |
| --- | ---: | ---: | ---: | ---: |
| 영어·아라 | 13.642초 | 56.464초 | 8091.65MiB | 12344.71MiB |
| 일본어·서연 | 13.203초 | 56.557초 | 8091.79MiB | 12398.51MiB |

생성+변환은 Worker totalSeconds이며 NAS 대기·업로드 시간은 포함하지 않는다. CUDA 할당 최대는 원곡 생성 단계, GPU 장치 메모리 표본 최대 9494/9459MiB는 다른 앱도 포함한다. 이를 전체 변환 단계의 모델 전용 최대 메모리로 해석하지 않는다.

- 영어 NAS 작업 `1fc5f7bc-77bf-4e53-8a12-8adeb12f4043`
- 일본어 NAS 작업 `c8116943-1d15-4df0-9db6-f04a02d065a9`
- WAV·MP3 네 파일을 NAS에서 다시 받아 크기·SHA-256·전체 디코딩·유한 PCM·피크를 검증했다. 모두 30초·48kHz·2채널이다.
- 각 운영 웹 음악 카드에서 오디오 readyState=4·duration=30, 실제 재생 paused=false·currentTime 증가를 확인했다. WAV 앱 라이브러리 저장 성공 메시지와 새로고침 후 언어·작업 카드 복원을 확인했다. 두 웹앱의 브라우저 오류 로그는 비어 있었다.
- 종료 시 Worker acceptingJobs=true·activeJobId=null·error=null. 신규 유료 호출 0.

실측·요청·결과·음원은 로컬 artifacts/multilingual-1360-production/에 보존했다. 새로운 두 출력의 발음·음색에 대한 사용자 청취 평가는 별도이며 기술 검증으로 품질을 단정하지 않는다.

## 후속 청취·장시간 검증

사용자는 운영 영어 아라·일본어 서연 30초 비교본에 “특별한 문제 없이 자연스러움”을 확인했다. 이후 무료 영어·일본어 아라·서연 각 60·120초 총 8곡의 운영 생성·WAV/MP3 무결성 검증을 완료했다. [장시간 실측 기록](./multilingual-long-persona-benchmark.md)에 성능·메모리·일시적 503 접수 거절과 재개·후반부 비교 방법을 기록한다. 후반부 비교 청취에서 영어는 잠정 수용됐고, 일본어는 괜찮게 들리지만 사용자가 발음 정확도를 판단하기 어려운 것으로 기록했다. 전체 가사 준수·일본어 발음 정확도 검증 완료로 확대하지 않는다. 새 기능 코드·버전·모델·CFG 변경이나 신규 유료 호출은 없다.
