# 가창 ASR 후보의 버전·입력 형식 분리 검증 — 2026-10-06

## 확인한 차이

[ACE-Step Transcriber의 고정 config](https://huggingface.co/ACE-Step/acestep-transcriber/blob/53062cf7d0e09d463d7fc4c218ce2ecb71400f29/config.json)는 `transformers_version=4.53.3`을 기록한다. 이전 비교는 5.18.0이었다. 이 기록은 체크포인트 저장 시 라이브러리 정보이며 전체 학습 환경을 재현했다는 증거는 아니다. 공개 `args.json`의 `template=qwen2_5_omni`, `template_backend=swift`, `system=null`, `torch_dtype=bfloat16`도 확인했다.

모델 저장소의 chat template는 시스템 메시지가 없을 때 일반 도움말 시스템 문구를 추가한다. 이전 비교는 이 기본값을 그대로 사용했다. [Qwen Omni의 4.53.3 공식 예제](https://huggingface.co/docs/transformers/v4.53.3/model_doc/qwen2_5_omni)는 별도의 Qwen Omni 시스템 메시지를 명시한다. 공식 예제의 문구는 음성 출력에도 관련되며, 기본값에서 발생하는 음성 출력 경고만으로 텍스트 받아쓰기 실패 원인을 확정할 수 없다.

## 분리한 실험

1. **전처리 비교:** 같은 중국어 기존 파일의 첫 30초 PCM과 같은 프롬프트로 4.53.3/5.18.0의 CPU 전처리를 비교했다. `input_ids`/`attention_mask` 크기 `(1,782)`, `feature_attention_mask` `(1,30000)`, `input_features` `(1,128,30000)`가 일치했다. 모든 값이 정확히 같고 최대 절대 차이는 0이다. 음향 placeholder 토큰은 750개다. 이 한 사례의 전처리 일치가 모든 음원 또는 모델 내부 계산의 일치를 입증하지는 않는다.
2. **버전 비교:** 4.53.3으로 이전 6곡 전체를 같은 기본 chat template/NF4/SDPA/greedy/최대 512 새 토큰/30초 창·3초 겹침으로 처리했다. 후보 revision, PCM 파일, 정답, 병합·필터·점수 계산은 고정했다.
3. **시스템 프롬프트 비교:** 4.53.3의 동일 모델과 실행 조건에서 공식 Qwen Omni 시스템 메시지만 추가했다. 중국어·태국어·베트남어 기존 3곡의 전체 파일, 총 7개 창을 비교했다. 곡 제목·정답·언어 힌트는 주지 않았다. 추가 3곡과 혼합하거나 전체 6곡 결과로 표시하지 않는다.

호환 환경은 Worker 가상환경을 바꾸지 않는 별도 디렉터리에 Transformers 4.53.3, tokenizers 0.21.4, huggingface-hub 0.36.2 및 필요한 requests 의존성을 설치했다. 처음 CPU import 때 `ModuleNotFoundError: No module named 'requests'`가 발생했고 해당 디렉터리에 requests 2.32.5를 설치해 해결했다. 토큰이나 사용자 음원을 전송하지 않았다. PyTorch 2.7.1+cu126와 bitsandbytes 0.49.2는 이전 비교와 같다. 패키지 호환 의존성도 함께 달라졌으므로 Transformers 코드 한 줄만의 영향을 분리했다고 주장하지 않는다.

모델 가중치의 누락·크기 불일치를 허용하지 않고 실제 파라미터가 모두 CUDA에 있는지 확인했다. 예상하지 않은 모델로의 자동 대체나 CPU/디스크 우회는 없다. 모든 네이티브 시험은 기존 GPU 잠금과 Worker 종료 후 복구 절차를 사용한다. 오류율과 RAM/GPU 측정의 정의·음원 출처·평가 한계는 [첫 비교 기록](singing-asr-validation-20261006.md)을 따른다.

## 버전 비교 결과

| 전체 파일 | 후보 NF4, 5.18.0 | 후보 NF4, 4.53.3 |
|---|---:|---:|
| 중국어 기존 CER | 767.86% | 767.86% |
| 중국어 추가 CER | 7,100.00% | 7,100.00% |
| 태국어 기존 CER | 433.33% | 556.94% |
| 태국어 추가 CER | 405.13% | 405.13% |
| 베트남어 기존 WER | 100.00% | 100.00% |
| 베트남어 추가 WER | 515.83% | 513.33% |

6곡 중 4곡은 병합된 출력 문자열도 정확히 같다. 태국어 기존은 악화했고 베트남어 추가는 2.5%p 낮아졌지만 여전히 심각한 삽입·반복 오류다. **체크포인트에 기록된 버전으로 맞추는 것만으로 실패를 해결하지 못했다.** 4.53.3 후보도 6곡 모두 기준 Qwen보다 나빴다.

4.53.3 로딩은 15.999초, 전체 6곡 추론 합계 281.859초였다. 로딩 포함 프로세스 working set 최고 5,675.00 MiB, 장치 전체 GPU 메모리 최고 8,907 MiB였다. 16개 창 중 6개가 512 토큰 한도에 도달했다. 이전 실행과 캐시·다른 앱 상태가 달라 작은 속도 차이를 일반적인 우열로 해석하지 않는다.

## 공식 시스템 프롬프트 결과

| 기존 전체 파일 | 기본 시스템, 4.53.3 | 공식 시스템, 4.53.3 | 기준 Qwen |
|---|---:|---:|---:|
| 중국어 CER | 767.86% | 480.95% | 11.90% |
| 태국어 CER | 556.94% | 556.94% | 84.72% |
| 베트남어 WER | 100.00% | 100.00% | 97.26% |

중국어 오류율 감소는 정확한 가사를 더 인식한 증거가 아니다. 두 후보 결과 모두 정렬상 정답 84자가 전부 치환됐고 삭제는 0개였다. 무관한 반복·설명 등의 삽입 오류가 561개 → 320개로 줄어 점수가 낮아졌다. 태국어·베트남어는 점수가 같다. 공식 시스템 조건도 3곡 모두 기준 Qwen보다 나쁘다.

공식 시스템 실행의 로딩은 15.821초, 전체 3곡 추론 합계 92.917초다. 로딩 포함 working set 최고 5,689.93 MiB, 장치 전체 GPU 메모리 최고 8,899 MiB, PyTorch 추론 할당 최고 6,283.08 MiB였다. 7개 창 중 2개가 토큰 한도에 도달했다. 두 번째 조건에는 음성 출력용 기본 시스템 경고가 없어졌지만 텍스트 인식 실패는 해결되지 않았다.

## 결론 및 확인 범위

추가 네이티브 추론 9개 전체 파일/23개 창과 CPU 전처리 비교를 완료했다. 전처리 일치, 기록된 라이브러리 버전, 공식 예제의 시스템 프롬프트를 확인했지만 **이 변경만으로 가사 인식 실패를 해결하지 못했다**. 후보는 제품에 추가하지 않으며 기본 Qwen과 제품 버전 1.28.2를 유지한다.

정확한 근본 원인은 미확정이다. 전체 학습·추론 스택을 재현한 시험이 아니며, 4.53.3에서 BF16 전체 파일과 NF4의 정확도 차이를 비교하지 않았다. 모델 특성·정밀도·가창 도메인 영향을 각각 확정했다고 주장하지 않는다. 이전 BF16 30초 실패도 한 사례에 대한 제한된 증거다. 모델 저장소에서 안내하는 50개 이상 언어 지원을 이 6곡의 정확도 보장으로 해석하지 않는다.

두 실행 모두 필요한 가중치의 누락/크기 불일치 없음, CUDA 배치, OOM 없음, Worker 복구 종료 코드 0을 확인했다. 최종 인증 health는 Worker 유휴/대기 작업 없음이며 NAS 브리지는 `IDLE`/`workerReady=true`였다. UI나 제품 소스는 변경하지 않아 별도 릴리스를 만들지 않는다. 점수·오류 개수·시간·메모리·WAV 해시와 전처리 비교 수치는 [측정 JSON](singing-asr-measurements-20261006.json)에 추가했다. 음원·가사 원문·특징 배열·로컬 인증 정보는 Git에 포함하지 않는다.
