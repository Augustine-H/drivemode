# 음악 생성·가사 인식 검증 — 1.28.1 (2026-10-06)

## 반영한 수정

- ACE-Step가 음악 설명 256토큰·가사 2048토큰을 조용히 자르던 동작을 방지한다. 모델의 실제 tokenizer와 prompt/언어/metadata/header/special token 형식을 그대로 계산하며, 한도 초과 시 내용을 줄이라는 오류를 반환한다. API의 문자 수 제한과 모델의 토큰 한도는 다르다. CUDA offload/추론 전에 확인한다.
- 입력 한도 초과는 `VocalInputLimit`으로 구분한다. 해당 작업은 실패하지만 Worker는 다음 요청을 받는다. 실제 확인 중 기존 공통 모델 오류 처리 때문에 첫 거부 뒤 HTTP 503이 발생하는 문제를 발견해 수정했다. 예상하지 못한 CUDA/모델 오류는 기존 중단 정책을 유지한다.
- 보컬 생성 설정을 8 steps, guidance 1.0, shift 3.0으로 명시하고 결과에 토큰 수·한도와 설정을 기록한다. 기존 turbo 모델은 CFG를 사용하지 않으므로 guidance 명시는 품질 향상 주장이 아니다. 모델·revision은 바꾸지 않는다.
- 가사 구간 합치기에서 Thai 모음·성조 등의 Unicode mark를 보존한다. 이전 `isalnum()`만 사용한 비교는 서로 다른 단어를 같은 경계로 취급할 수 있었다. 불확실한 경계는 원문 둘을 보존한다.
- `lyrics_evaluation.py`는 정답을 추론에 전달하지 않는 오프라인 CER/WER 계산을 제공한다. 누락·삽입·반복을 모두 채점하고, 빈 정답은 정의되지 않은 오류율, 과도한 반복은 100% 초과 오류율로 남긴다. 음운/한자 읽기 동등성을 추측하지 않는다.

## 보컬 생성 안정성·품질

RTX 4070 Ti에서 자체 작성한 한국어 가사로 30/60/120초 × seed 1042/2026의 6곡을 연속 생성한 뒤, 각각 가사를 받아썼다. 생성/인식 모델을 같은 GPU 큐에서 교대로 사용하는 추가 비교도 진행했다. 아래는 기본 음악 설명으로 생성한 최초 6건의 모델 로딩·생성 측정이며 API 대기/MP3 변환 시간과 다르다.

생성 자식 프로세스의 최대 샘플링 RAM은 12432.89 MiB. 전체 GPU 사용량 최고 10725 MiB는 다른 앱 사용량도 포함한다. 마지막 GPU 사용량 1603 MiB, Worker 유휴 복귀를 확인했다. 부모 Worker RAM 식별은 측정 스크립트의 경로 매칭에서 실패해 기록이 null이며 메모리 누수가 없다고 단정하지 않는다. 6건 연속 검증은 수일 상시 서비스의 안정성 검증을 대신하지 않는다.

6개 WAV는 48kHz stereo, 실제 길이 각각 30/60/120초, 유한 표본, native peak 약 0.8913 및 포화 표본 0을 확인했다. 6개 MP3 320 kbps를 끝까지 decode해 길이를 확인했고 다운로드 바이트·SHA-256이 Worker 메타데이터와 일치했다. ASR용 16kHz mono 변환의 peak/포화율은 원본 WAV의 지표와 구별한다. 모든 완료 작업에서 입력 오디오와 임시 요청 파일 제거를 확인했다.

## 로컬 기록과 남은 범위

수정 Worker의 실제 API 작업 9건(음악 설명/가사 한도 초과 2건, 정상 생성 2건, 그 음원 받아쓰기 2건, 중국어/태국어/베트남어 받아쓰기 3건)을 완료했다. 한도 초과 2건은 의도한 실패이며 음원 파일을 쓰지 않고 입력 개수·한도만 오류로 알렸다. 재시작 없이 이어지는 정상 생성과 인식을 처리했고 마지막 `acceptingJobs=true`, 활성 작업 없음 및 NAS 브리지 `IDLE/workerReady=true`를 확인했다. 기본 30초 Worker 창의 언어 점수는 각각 11.90%/80.56%/97.26%로 네이티브 비교와 일치했다.

실제 고정 tokenizer 준비용 검사에서 최신 Hugging Face `snapshot_download(local_files_only=True)`의 전체 snapshot 검증이 `.gitattributes`, `README.md`, `silence_latent.pt` 미캐시로 `IncompleteSnapshotError`를 반환했다. 이 검사는 생성 파이프라인을 실행한 검사가 아닌 tokenizer 단독 준비 검사였다. 실제 생성에 쓰고 있던 동일 고정 revision의 `tokenizer/tokenizer.json` 경로를 `try_to_load_from_cache`로 확인해 그 디렉터리의 실제 tokenizer로 검사했다. 다른 모델이나 원격 다운로드로 대체하지 않았다. 정상 입력 허용, 1373/256 설명 거부, 6012/2048 가사 거부를 확인했다.

음악 서비스 Python 테스트 64개, TypeScript 검사, 프로덕션 빌드 및 변경 파일 whitespace 검사가 통과했다. 개발/빌드 화면에서 1.28.1과 실제 대화·가사 내용 렌더링, 페이지 가로 넘침 없음 및 브라우저 콘솔 오류 없음을 확인했다. 브라우저가 실제로 보고한 폭은 개발 558px/빌드 337px이며, 요청한 1280px viewport override가 적용되지 않아 이번 검증을 1280px 데스크톱 검증으로 주장하지 않는다. UI 레이아웃은 이전 릴리스와 같고 표시 버전만 변경했다. Windows에서는 기존 `preview:restart`의 Linux `/proc` 검사가 no-op이므로, 기존 Windows 시작 스크립트로 해당 Vite preview 프로세스만 확인 후 재시작했다.

- `.music-runtime/qwen-asr/expanded-comparison/{report,evaluation}.json`: 고정 모델 비교.
- `.music-runtime/qwen-asr/requested-window-comparison/{report,evaluation}.json`: 3개 우선 언어의 분할 비교.
- `.music-runtime/qwen-asr/expanded-20261006/manifest.json`: 공개 음원의 출처·해시·범위·시간 자막.
- `.music-runtime/vocal-verification/extended-20261006/{report,evaluation}.json`: 6곡 파일·자원·가사 일치 프록시.
- `.music-runtime/vocal-verification/release-1281/report.json`: 입력 한도 거부 뒤 정상 작업 처리, 생성 설명 후보, 수정 Worker의 3개 언어 검증.

태국어/베트남어 현대 대중가요의 여러 가수·조건에 대한 정답 정렬 자료, 확실한 음향 인식 개선 방법, 보컬 인간 청취 평가는 남아 있다. 이번 변경은 새 모델 학습이나 제품 전체 정확도 개선을 의미하지 않는다. 저장체계 호환 버전은 유지한다. 운영 배포 확인은 이번 2·3·4번 범위에 포함하지 않는다.
